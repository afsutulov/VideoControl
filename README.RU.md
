# VideoControl

[English](README.md)

**VideoControl** — небольшой сервис на Go для записи видео с RTSP-камер при обнаружении движения. Он предназначен для небольших систем умного дома: сохраняет MP4-файлы локально, может уведомлять внешнюю систему через файл и загружать завершённые записи в Яндекс Диск или другое WebDAV-хранилище.

Проект можно использовать самостоятельно или вместе со [SmartHome](https://github.com/afsutulov/SmartHome). Версия приложения в текущем исходном коде — **1.0.0**.

## Возможности

- Одновременная обработка нескольких RTSP-камер; каждую камеру можно включить или отключить в конфигурации.
- Обнаружение движения с помощью OpenCV и GoCV.
- Запись цветного видео в MP4 с настраиваемыми размером кадра, кодеком и частотой кадров файла.
- Продолжение записи после последнего обнаруженного движения.
- Хранение записей по камерам и датам.
- Переподключение к камере при ошибке чтения потока.
- Файл уведомления с локальным путём к завершённой записи.
- Необязательная фоновая загрузка записей по WebDAV.
- Журналирование в файл, консоль или одновременно в оба места.
- Конфигурация в JSON и пример службы systemd.

## Как работает запись

Сервис уменьшает каждый кадр до заданного размера, переводит его в оттенки серого и сравнивает с предыдущим кадром. Если площадь контура изменений превышает заданный порог, начинается запись. Каждое новое обнаружение движения продлевает её; после периода без движения, указанного в `post_recording`, файл закрывается.

Затем сервис записывает путь к видео в файл уведомления и запускает загрузку по WebDAV, если эти функции включены. Локальный файл сохраняется и после загрузки.

VideoControl работает как фоновый процесс. В текущей реализации нет веб-интерфейса, распознавания объектов, встроенного MQTT-клиента и автоматического удаления старых записей.

## Требования

Основной сценарий развёртывания — **Linux-сервер**.

- Go **1.22 или новее**.
- Компилятор C/C++ и поддержка CGO.
- **GoCV v0.40.0** — версия зафиксирована в `go.mod`.
- **OpenCV 4.11.0** и необходимые дополнительные модули: эта версия указана в [инструкции GoCV v0.40.0](https://github.com/hybridgroup/gocv/blob/v0.40.0/README.md#installation).
- Рабочий видеобэкенд OpenCV для RTSP и выбранного кодека записи.
- Доступ к RTSP-камерам и право записи в каталоги хранения, журналов и уведомлений.

Перед сборкой установите OpenCV по инструкции для GoCV v0.40.0. Сам GoCV загрузится как зависимость Go. При обычной сборке Linux библиотеки OpenCV также нужны на машине, где запускается программа.

## Сборка

После установки зависимостей:

```bash
git clone https://github.com/afsutulov/VideoControl.git
cd VideoControl
go mod download
CGO_ENABLED=1 go build -o VideoControl .
```

Проверка версии:

```bash
./VideoControl --version
```

## Быстрый запуск

Скопируйте пример конфигурации в локальный файл:

```bash
cp configs/videocontrol.conf.example.json ./videocontrol.conf
```

Отредактируйте `videocontrol.conf`:

1. Укажите адреса, логины и пароли камер в `cameras`.
2. Включите нужные камеры через `enabled: true`.
3. Выберите каталог `storage.base_dir`, доступный для записи.
4. Настройте журналирование. Для запуска без прав администратора можно установить `logging.file` в пустую строку, а `logging.to_console` — в `true`.
5. При необходимости настройте `notification_file` и `webdav`.

В примере из репозитория используются `/share`, `/var/log/videocontrol.log` и включён файл уведомлений `/share/video.save`. Для запуска от обычного пользователя измените эти пути или предоставьте необходимые права.

Запустите наблюдение:

```bash
./VideoControl --run --config ./videocontrol.conf
```

Остановка — `Ctrl+C`. Подробное описание всех параметров, значений по умолчанию и примеры приведены в [CONFIGURATION.md](docs/CONFIGURATION.md).

## Параметры командной строки

| Параметр | Назначение |
| --- | --- |
| `--run` | Запустить наблюдение за камерами. |
| `--config PATH`, `-c PATH` | Указать JSON-конфигурацию. По умолчанию: `/etc/videocontrol.conf`. |
| `--version` | Вывести название и версию приложения и завершить работу. |
| `--help` | Вывести справку по флагам. |

Без `--run` программа показывает краткую справку и завершается, не подключаясь к камерам.

## Установка как службы systemd

Выполняйте команды из корня репозитория после сборки:

```bash
sudo bash ./scripts/install-systemd.sh
sudo nano /etc/videocontrol.conf
sudo chmod 600 /etc/videocontrol.conf
sudo systemctl start videocontrol
sudo systemctl status videocontrol
```

Скрипт устанавливает программу в `/usr/local/bin/VideoControl`, создаёт конфигурацию, если её ещё нет, копирует unit-файл и включает автозапуск. Сам сервис скрипт не запускает — сначала нужно настроить камеры.

Пример unit-файла запускает процесс от `root`. Если выбрана другая учётная запись, ей нужны права чтения конфигурации и записи в используемые каталоги.

Полезные команды:

```bash
sudo systemctl stop videocontrol
sudo systemctl restart videocontrol
sudo journalctl -u videocontrol -f
```

При `logging.file` с непустым значением и `logging.to_console: false` основной журнал приложения находится в указанном файле. Например:

```bash
sudo tail -f /var/log/videocontrol.log
```

После изменения конфигурации перезапустите службу.

## Хранение записей

Для камеры с именем `Front Door` локальный путь имеет вид:

```text
/share/Front Door/2026/10/12/12-30-45.mp4
```

Если имя камеры не задано, используется её `id`. Дата и время в локальном пути соответствуют началу записи и часовому поясу сервера.

При `webdav.remote_base_dir: "Camera"` удалённый путь обычно выглядит так:

```text
Camera/Front Door/2026/10/12/12-30-45.mp4
```

Дата удалённого каталога определяется в момент завершения записи; у ролика, пересёкшего полночь, она может отличаться от даты локального каталога.

## WebDAV и Яндекс Диск

Для облачной загрузки задайте `webdav.enabled: true`, адрес сервера, имя пользователя и пароль. Пример блока для Яндекс Диска приведён в [CONFIGURATION.md](docs/CONFIGURATION.md#webdav).

Сервис использует HTTP Basic Auth, создаёт удалённые каталоги через `MKCOL` и загружает файлы через `PUT`. Для Яндекс Диска используйте подходящий пароль приложения. Загрузка выполняется после обычного завершения записи и не удаляет локальную копию. Автоматического повторения неудачной загрузки нет.

## Интеграция со SmartHome

При включённом `notification_file` сервис перезаписывает указанный файл локальным путём к завершённому видео. Например, файл `/share/video.save` будет содержать:

```text
/share/Front Door/2026/10/12/12-30-45.mp4
```

Внешний сервис может следить за этим файлом и обрабатывать новые записи, например отправлять уведомления в Telegram. VideoControl сам не отправляет сообщения в Telegram или MQTT. Файл содержит только последний записанный путь и не является очередью событий.

## Диагностика

| Ситуация | Что проверить |
| --- | --- |
| Сборка сообщает об отсутствии `opencv4` или заголовков OpenCV | Установлены ли OpenCV и дополнительные модули нужной версии; корректны ли настройки `pkg-config` и пути библиотек. |
| Ошибка `config error` | Валидность JSON, названия полей и наличие хотя бы одной включённой камеры с уникальным `id` и непустым `rtsp`. |
| Ошибка `logging error` | Уровень журнала и права записи в каталог лог-файла. |
| Камера постоянно переподключается | RTSP-адрес, учётные данные, доступность камеры и поддержку потока видеобэкендом OpenCV. |
| Нет записей или слишком много срабатываний | Настройки `motion.threshold` и `motion.min_contour_area`; качество и размер кадров. |
| Записи воспроизводятся с неправильной скоростью | Соответствие `recording.fps` фактическому темпу поступления кадров: этот параметр не ограничивает чтение RTSP. |
| Не проходит облачная загрузка | URL, учётные данные WebDAV, права создания каталогов и свободное место; сообщения `[WARN]` в журнале. |
